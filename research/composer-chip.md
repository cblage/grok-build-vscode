# Composer chip

`#gear-btn` remains the composer control. `openGearPopover` opens the model picker directly from it; the rail gear keeps its app menu. `renderGearApp(target)` supplies the same purpose, Remote Control and Settings actions to VS Code's `+` menu, where each group has a heading. Rail surfaces keep their upload-only `+` menu.

`syncModelChip` shows the model name and effective effort, and nothing else. The provider glyph and the chevron were both there first and both came off: the model name already spells the provider out, and a chevron on this button with none on the mode button beside it made one of two identical toolbar-button-opens-popover controls look like the menu. Removing the glyph also removed the narrowest rung's fallback, so the name now narrows rather than hiding -- an empty button is not a smaller button. The picker's own rows keep their glyphs; that is where provider identity is actually being chosen. `renderEffortStrip` uses the model's advertised ladder, with the existing fallback ladder for older metadata. Rail and gradient fill occupy the same box; `clip-path` reveals a slice instead of compressing the gradient. The knob interpolates the same palette anchors. The model list is the only scroller; effort and Manage providers stay pinned. Selection can lock while the chip and provider recovery remain actionable.

The PICKER previews while open and commits once, on close -- the effort strip and the model list alike. Committing on every tap was unusable on an empty session, which is the common case on a phone: the host does not apply effort live there, it restarts the session, `busy` locks the strip mid-gesture, and the host's own `session.priming` guard drops every later change -- so a mis-tap could not be corrected until the restart finished, which reads as "nothing happens". One commit at the end is also one restart, not one per stop a finger crosses. `closePopovers` is the single funnel, so no dismissal route can skip it, and returning to the value you started on posts nothing at all. The knob also drags: the track is a grid of equal columns, so the column under the pointer IS the stop, pointer capture keeps the gesture alive when the finger leaves the band, and `touch-action: none` stops the popover scrolling underneath it.

The model list joined the strip on the same terms: picking a model used to post and close, so "this model at that effort" cost two visits and the second could not start until the first had finished restarting. `previewModel` writes `state.currentModelId` and `state.activeProvider` instead, which is what makes the display optimistic -- reopen the picker before the host has applied anything and it still shows what was picked. A level previewed against the PREVIOUS model survives only while the new one still advertises it: an off-menu level is refused by the adapter, and committing one would leave the strip showing something the session never ran at. `""` is every model's default and always survives.

`flushPicker` sends ONE message. Two posts would race: the host does not serialize its async message handlers, so a `setEffort` that restarts could read the remembered model back before the `setModel` beside it had written one. The level therefore rides on `setModel.effort`, and one close causes at most ONE restart: the host remembers the level BEFORE the switch, against the provider the switch aims at, so a restart the switch triggers spawns at it, and it applies the level live afterwards only when the session id did not change -- a compatible switch carries a live effort override through when the target advertises it, so the level has to be re-stated to settle a disagreement between the two. That comparison is load-bearing rather than tidy: `startSession` clears `hasHistory`, so a Summarize & Restart leaves a session that HOLDS the summary looking empty, and the effort path read it that way, deleted it on disk and restarted again -- the person asked to keep the thread and got a blank one. The same comparison collapses the cross-provider double restart that used to be an accepted residue. A host too old to read the field applies the model and ignores the level; the strip then reconciles to what the session runs at, and changing effort alone still works. `trackPickerChange` keeps the in-flight commit in a promise `handleSend` settles before it reads session readiness, so a change lands before the message it was chosen for -- bounded by `releasePickerWaits`, because a restart prompt is a question to the user and a notification nobody answers must not swallow the send queued behind it. `sendOrStop` flushes the picker itself rather than leaning on the document's close listener: that listener is on the bubble phase, so the send button's own handler runs first and `send` would otherwise reach the host ahead of `setModel`. Keeping the picker open is exactly what makes "pick a model, then press Send" the ordinary gesture, so the ordering this feature needs is the one the feature itself made easy to break.

For an adapter the spawned client also publishes the effort the session is ABOUT to be configured with. `session/new` advertises the CLI's own configured default, `AcpClient.newSession` applies the requested level a moment later over `set_config_option`, and the `session` event -- the frame the host turns into the picker's catalog -- fires in between. Publishing the default there is what made a Codex effort change snap back: the strip redrew at `gpt-6-astra`'s configured `ultra` and nothing afterwards corrected it, because `setReasoningEffort` emits no event and the `modelChanged` a model switch emits keeps an in-ladder level. Only a level the current model advertises is published, since an off-menu one is refused by the adapter and the CLI's value is then the honest thing to show. Grok never had this: its effort is a spawn flag, so `session/new` already answers with the new level -- which is why the symptom looked provider-specific. Claude escapes it only by accident, its default effort being the literal `"default"` that `modelsFromClaudeConfigOptions` drops.

Effort is optimistic and reconciles on the next `initialState` — the same promise the effort dots kept before the chip. `setEffort` deliberately sends **nothing** back: `emit` both buffers into the session replay and fans to every remote holding the conversation, and `initialState` is action-shaped there (`restoreRememberedRemoteSession` posts `resumeSession` from it), so acknowledging with that frame made a phone clear and replay its own transcript and drop an in-flight recording on every effort or model change. The residue, stated plainly: dismiss the restart prompt and the chip shows the level you picked until the conversation next reloads. `test/mode-prefs.test.ts` pins the silence.

Model metadata supplies effective effort when advertised. An older host with no effective-effort metadata gets no guessed chip word; the strip says Default until the host supplies the value. An incompatible model ladder resets to the advertised effort and announces the change — client-side, from `modelChanged` alone.

The `--e1`–`--e4` ramp is fixed hex in `:root` with a `body.vscode-light` override, matched byte for byte by the desktop shim and the relay page so one effort is one colour everywhere. That selector does not match VS Code's High Contrast Light, so the strip renders the dark ramp there — a regression against the old dots, which took `--vscode-button-background` and so followed any theme. Accepted knowingly rather than half-fixed: the stylesheet's whole light-override system already sits behind the same selector (the diff add/delete/read/modify palette among it), no gate covers HC Light, and serving this one control there while the rest stays dark is the worse of the two states. `npm run e2e:hc-colour` covers HC **dark**, where the knob reads at 5.89:1.

The donut's own numbers are the ladder's first rung, above the mode word: they are the one readout here nothing in the message depends on, and the tooltip and popover both still carry them. Wide non-touch surfaces keep them; touch drops them outright, as it did before the chip existed. Below a 250px card on touch the donut itself goes — six controls at a 36px tap floor need more room than that rung has, and a control too small to hit is worse than one honestly absent. Its touch rules live in the later coarse-pointer block beside `#donut-label`, not in the composer's own: `.context-donut` is declared further down this stylesheet at the same specificity, so an earlier copy is simply overwritten.

The existing `.composer-card` inline-size container is intentional: fixed rail popovers are its siblings, so their containing block stays unchanged. It measures the card content box after the outer composer's gutters and card border. A measured 334px VS Code composer has a 324px query box. Mode text drops at 430px, effort at 300px, model text is capped at 272px and again at 44px below 224px. Touch always hides effort and caps the model name at 296px, then at 52px below 250px. Neither ladder ends in a hidden name any more. Long model names also use ordinary flex ellipsis.

The mic node is immediately after `+` in `.toolbar-left`. New host markup puts it there; renderer startup moves the existing node for older shells. The textarea and highlight share symmetric 8px horizontal padding. Voice states retain their existing classes and animations.

`contextFullnessColor` serves both the donut and the single context bar. Thresholds are strictly greater than 70 and 90 on the rounded percentage. Both purposes reveal the bar and secondary Compact button; the coding ledger remains below them.

The ledger's figures are compact -- `compactTokens`: thousands and millions, two decimals below the hundred and none above it, trailing zeros dropped, so 1.48K, 10.28K, 499K, 500K, 1.2M. Under a thousand the exact number is short enough to say outright, and above 999,500 the K branch would round to "1,000K", which is a million wearing the wrong unit. Coarser than it looks is the point: the ledger answers "how much room is left", and 498,525 answers that no better than 499K while costing a column wide enough to break a number in half on a phone -- the donut's tooltip still carries the exact figure. The popover sizes to `width: max-content` with `max-width` doing the capping, because shrink-to-fit plus the rows' `overflow-wrap: anywhere` sized the box toward MIN-content and split `10,284` into "10,28" and "4"; a figure is one word however its label behaves, so the value cell is `nowrap` with `overflow-wrap: normal`. Touch keeps its `min(94vw, 420px)` cap, which already clears the 80% the ask named.

## Verification

- `test/codex-acp-integration.test.ts`: the catalog the `session` event publishes carries an advertised requested level and leaves an off-menu one at the CLI's own.
- `test/composer-chip.dom.test.ts`: direct picker, signed-out recovery, advertised efforts and keyboard controls, reconciliation, flat app-menu sequences and context thresholds in both purposes.
- `test/mode-prefs.test.ts`: host reconciliation on success, refusal, priming and cancelled restart for the existing message contract.
- `npm run e2e:composer`: Chromium renders shipped markup, scripts, CSS and palettes across four surface fixtures, two themes and nine widths, including the desktop shell's wrappers and spacing. It measures rendered text and ancestor clipping at 334px, each collapse rung, real truncation, all toolbar controls, mic padding/size, pinned scrolling, matching rail/fill boxes, reduced motion and visible context controls. Screenshots and measurements are in `.screens/composer/`.

The browser fixtures use this repository's shared renderer and owned palette; they do not load the relay's downstream page overrides. The relay half landed alongside this one: `syncRemoteUploadRows` now finds `[data-upload-row="photo"]` and inserts Add document directly after it, the page's own composer markup matches this one, its 46px/8px mic-lane overrides and dead `.effort-dot`/`.model-name-btn` rules are gone, it carries the same effort ramp in both themes, and `scripts/touch-ui-check.mjs` asserts the deleted lane on the surface that actually had it.
